## 2. Spec and design points found (not edited: protocol.md, protocol/ and the design are not mine)

1. **A sensitive post needs a body.** Spec: a post with no `title`, `text`, `bigText`, `messages` or `lines` (and not `redacted`) is `bad_request`; decision 1 says a flagged app sends only its name. The phone therefore sends `title` = the app name for a sensitive post (no content, and the PC shows "Private notification" anyway). If the desktop agent wants an exemption (`sensitive` posts may be empty) the phone can send nothing else.
2. **OTP "at least 10 characters closer"** vs the spec's own example "Verification code 123456 or 654321 -> none": the second code is exactly 10 characters farther, so the rule has to be *more than* 10. Implemented as `> 10`.
3. **`label` of a reply** is the post's hint (the empty string when none), "cut to 30 like any label" while a hint is 60: the phone compares `clean(remote-input label, 30)` with the cleaned `label`.
4. **`Ranking.getLockscreenVisibilityOverride()` is API 31**, not 28 (design 4.4 rule 10). Found by the **API 29 emulator**: a `NoSuchMethodError` killed the process on the first notification (and lint's `NewApi` then confirmed it). Guarded; on Android 10 to 11 the app's own `visibility` is all there is.
5. **API 29 and 30 cannot tell an activity action** (`PendingIntent.isActivity()` is API 31): "Open" **is offered** there (seen on the emulator: `actions=Mark as read,Open`), and pressing it from the PC is acked ("sent to the app") while Android silently blocks the start. Known limit of the design (4.7); the PC cannot know. Worth a line in TESTING.md.
6. **Notifications posted before the listener is connected are never delivered to it**, so they are not mirrored (consistent with "no pre-existing notifications"). After granting access, or after a rebind, the first second or two are blind.
7. **Frame sizes:** the spec now allows 48 KiB for `notif.icon`; the phone's own PNGs stay under 12,000 bytes so every frame it sends is under 16 KiB.
8. Android's `cmd notification post` is limited to **50 notifications per package** and the shell has no "cancel all": the debug command `MIRROR_CLEAR_ALL` (through the listener, skipping Kin's own foreground-service notification: cancelling that one **kills the process on API 29**) is test hygiene only.

## 5. Cleanup list and open items

- **Desktop/PC side of the spec:** points 1 to 3 of section 2 need a yes from the spec owner; the phone follows what the spec says today.
- `verify-2b2.ps1` and `verify-2b2-desktop.ps1` (new, android\tools) leave nothing behind: the emulator, the stub (gradle test worker) and the test Kin are stopped by ID, the listener access is revoked, the shade is cleared (except Kin's own notifications), the PC clipboard is never touched; their temp folders (`%LOCALAPPDATA%\Temp\kin-verify-2b2-*`) were deleted after the runs.
- `FakePcSession` now lists `notif` and can send `notif.dismiss`, `notif.action` and a new `hello` (commands in its header); `protocol/NotifInbound.kt` is test-support code that ships in the app (small, never called by it): moving it to the test source set is possible if the reviewer prefers (the main `MessageReceiver` has the `ReceiverRole.PC` branch that uses it).
- TESTING.md items for the user's phone: the restricted-settings flow, the Android 15+ redaction (R20), real messaging apps' reply and buttons (R24: WhatsApp, Telegram, Signal, Google Messages), "Open" on Android 10 and 11 (finding 5), the battery measurement, OEM listener unbinding (R25).
- The `<queries>` `MAIN`/`LAUNCHER` entry (decision 6, risk R27) draws a Play review question; the fallback (list only the packages that posted) is not built.
- A flagged app that the user turned on is mirrored in `sensitive` form only; **there is no way to see its content on the PC by design** (decision 1).

## 6. Review round 1 fixes

The reviewer blocked 2B.2 on one privacy finding (B1). Fixed, plus the Android cleanups. No emulator, no `assembleDebug` or `assembleRelease` this round (the integration run was using the APKs): `gradlew testDebugUnitTest lintDebug` once in the foreground, **650 tests, 0 failures, 1 skipped** (646 + 4 new), lint 0 errors. The APKs in section 4 are therefore **not rebuilt**: they do not contain these fixes yet.

**B1 (blocking).** `ActionHandler` read an active notification's content before checking the master switch and the allow list, and told `not_found` from `disabled`, so a paired PC could probe whether an app (a bank) had a notification. Now: `ActionPort` has `quick(sbn)`; `onAction` answers `disabled` right after `policy()` when mirroring is off, **before any lookup**; after the lookup it runs `filter.pre(port.quick(sbn), current)` and a notification of an app that is not ticked (or Kin's own, or another profile) answers `not_found`, the same text as a missing one, **before `snapshot()`**; `onDismiss` does the same `pre` check before `snapshot()`. Tests (`ActionHandlerTest`, +3): a live notification of an unticked app answers exactly like a missing one and `snapshot` is never called; mirroring off answers `disabled` with no `active()` call and no `snapshot`; a dismiss of an unticked app reads nothing. `theFiveStepsAnswerInOrder` now expects `not_found` for an unticked app (it was `disabled`).

**Cleanups.**
1. The stray root `MirrorListenerService.kt` is deleted; its `cancelAll()` (Kin's own notifications stay, so the foreground-service notification is never cancelled) is ported into `notifmirror/MirrorListenerService.kt`.
2. `onListenerConnected` cancels the old worker before it starts a new one.
3. Reasons 10 and 11 are no longer ignored (`IGNORED_REMOVE_REASONS` = 13, 16): another listener (a watch) dismissing a notification now removes the PC toast, and Kin's own cancel is recognised by the 5-second self-cancel memory. `selfCancelled` is a `ConcurrentHashMap`; the `ActionHandler` rate-limit queue is under a lock. Tests: `MirrorEngineTest` (a listener cancel sends `notif.remove`), `MirrorFilterTest` (the set).
4. A repeated `notif.action` ID while the first is still firing is ignored: `LinkSession` keeps a set of IDs in progress (added before the launch, removed after the answer is recorded and sent).
5. The allow-list and hidden-on-lock-screen toggles on the Apps screen are done inside one `DataStore.edit` (`toggleAllowed`, `toggleHiddenAllowed`): no lost update, no re-tick.
6. `AndroidIcons.forPackage` catches any exception (and `OutOfMemoryError`) from drawing and posts without an icon.
7. `WirePost.fit()` drops a lone high surrogate when it halves the text (test `fitNeverCutsThroughASurrogatePair`); `MirrorSender` keeps at most 500 per-`nid` states (oldest idle ones go first); the stale icon comment at `NotifWire.kt` now says the `notif.icon` frame limit is 48 KiB; a flagged or hidden (`sensitive`) post no longer reads or sends the app icon (`MirrorEngineTest` checks `iconReads == 0`).

**Toast form (desktop review item 8).** `NotifWire.toastForm` (U+2028, U+2029, U+FFFE, U+FFFF become a space, ends trimmed) and `cleanLabel` = `clean(toastForm(x), n)`. `ActionHandler` compares `cleanLabel(own label or hint, 30)` with the received label (also put in toast form when parsed); a button whose toast-form label is empty is `stale`, never fired. `NotifEncoder.pickActions` sends hints and button labels in toast form and does not offer a button whose label is empty in that form (a hint of only separators is no hint). Tests: `NotifVectorsTest` runs `toastLabel[]` (+ idempotent), `NotifEncoderTest` and `ActionHandlerTest` +1 each; `gradlew testDebugUnitTest lintDebug` once: **653 tests, 0 failures, 1 skipped**, lint 0 errors; APKs still not rebuilt.

It was not in git. It was **rebuilt from the compiled test class** (`javap`) of the earlier run: the same 19 test names with their values, strings and limits, written again by hand (the helper signatures and a few assertions were inferred from the bytecode), plus the new surrogate test. All 20 pass against the unchanged encoder, and the suite count is as expected (538 + 108 + 4), but the file is **not identical** to the original: the reviewer should read it once.
